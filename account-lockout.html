Lockout state

Repeated failed sign-ins should trigger a clear, controlled stop.

This preview uses Priya Shah's coordinator account. A lockout is not just an error state. It is a review event with operational and audit consequences.

Trigger

Five failed attempts from one device within 14 minutes.

Next step

Identity check, admin review, then unlock or forced reset.

System response

Audit entry created and dashboard queue updated.

Brutal note

Lockout handling cannot be an afterthought. If the PRD does not define it, support staff will invent inconsistent behaviour under pressure.
