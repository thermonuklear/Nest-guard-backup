This is the web app the PRD was trying to describe.

Brutal version: the original single-file prototype was still too much of a presentation deck. This rebuild treats the PRD as an application map and turns it into route-based HTML pages with role-specific navigation, realistic data, and screens that behave like a real platform.

Brutal product read

  • Notifications belong in Phase 1, not Phase 3.
  • The admin dashboard must prioritise risk, not vanity counts.
  • Student onboarding needs staged capture, or staff will hate it.
  • The parent portal should not drift into finance admin.
  • The student portal lives or dies on emergency visibility.

What changed from the first attempt

  • Moved from one showcase page to separate app-like routes.
  • Added shared visual system so pages feel like one product.
  • Split parent and student views instead of burying them in admin-heavy layouts.
  • Used route names that match actual navigation, not just epic names.

Static constraints preserved

  • No JavaScript.
  • No animations, transitions, hover changes, or sticky behaviour.
  • No hidden content or collapsed sections.
  • Everything visible on load across all routes.
